## Why this lesson matters

When a request crosses services, a single dashboard is rarely enough. This lesson focuses on building signals that let teams understand behavior they did not predict in advance.

- Metrics show patterns and thresholds.
- Logs provide narrative detail when designed consistently.
- Traces connect work across service boundaries.

## Core study path

Study each telemetry type by asking what question it answers during a real incident.

- Start with user-facing outcomes and service ownership.
- Add correlation IDs and trace context across boundaries.
- Keep alerts tied to action, not just activity.

## Practice cues

Choose a user journey and list the questions you would need to answer when it slows down.

- Identify the service that starts the trace.
- Define the signal that represents user pain.
- Remove alerts that no team knows how to act on.
