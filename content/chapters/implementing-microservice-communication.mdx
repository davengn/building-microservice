## Why this lesson matters

Implementation details decide whether a communication style stays maintainable. This lesson moves from architectural intent to concrete practices for APIs, messages, gateways, and compatibility.

- Contract changes can become deployment coordination problems.
- Gateways simplify clients but can become hidden monoliths.
- Messaging infrastructure needs operational ownership.

## Core study path

Read by following a request or message across service boundaries. At each hop, ask how the contract is described, versioned, observed, and retired.

- Prefer explicit contracts over accidental payload sharing.
- Treat backward compatibility as a release discipline.
- Use infrastructure to clarify ownership, not to hide coupling.

## Practice cues

Take an API you know and design a non-breaking change. Then design the same change as an event contract and compare the operational responsibilities.

- Define which consumers must keep working during the change.
- Decide how old versions are detected and removed.
- Add telemetry that proves the migration is safe.
