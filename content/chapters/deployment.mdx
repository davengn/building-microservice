## Why this lesson matters

Independent deployability is one of the main reasons to accept microservice complexity. This lesson focuses on the mechanics that make releases routine instead of dramatic.

- Rollout strategy should reflect the blast radius of the change.
- Rollback needs compatibility and state planning.
- Deployment telemetry should answer whether the release is healthy.

## Core study path

Follow a release from artifact to production. Ask how the team controls exposure, detects trouble, and recovers without waiting on unrelated services.

- Use automation to make releases repeatable.
- Prefer small changes that can be observed quickly.
- Keep deployment and operational ownership close together.

## Practice cues

Design a rollout plan for a risky service change. Include the first cohort, health checks, rollback trigger, and communication plan.

- Define what "healthy" means before releasing.
- Decide how configuration and schema changes are coordinated.
- Keep manual approval focused on risk, not ceremony.
