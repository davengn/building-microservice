## Why this lesson matters

Most teams do not start with a clean microservice landscape. This lesson helps you treat decomposition as risk-managed change rather than a rewrite narrative.

- Extract when the new boundary has a clear reason.
- Keep rollback and coexistence in the migration plan.
- Expect data ownership to be the hardest part of the work.

## Core study path

Read with a migration lens. Look for techniques that let old and new code coexist while the team learns whether the target boundary is actually useful.

- Start with the pain point you want to relieve.
- Choose a slice small enough to observe and reverse.
- Use contracts and telemetry to keep the transition visible.

## Practice cues

Choose one monolith feature and write a split plan in three steps. Each step should have a user-safe fallback and a signal that tells you whether to continue.

- Name the first behavior you would route to the new service.
- List the data that cannot move immediately.
- Define a success signal that is not just "service exists."
