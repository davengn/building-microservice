## Why this lesson matters

Users experience a system as workflows, not services. This lesson studies how UI architecture can either respect service ownership or reintroduce hidden coordination.

- A frontend can become the place where service complexity leaks.
- Backend-for-frontend layers can clarify client needs.
- Shared UI foundations need ownership and release discipline.

## Core study path

Study each composition option by asking how it affects product teams, performance, and the ability to change a user journey safely.

- Keep user workflow ownership clear.
- Avoid making every screen wait on every service.
- Treat aggregation APIs as product contracts.

## Practice cues

Map one page to the services it needs. Decide whether composition belongs in the browser, at an edge layer, or in a product-specific backend.

- Identify the slowest dependency in the page.
- Decide who owns the user-facing error state.
- Check whether shared UI code forces synchronized releases.
