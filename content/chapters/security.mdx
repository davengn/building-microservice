## Why this lesson matters

Microservices multiply trust boundaries. This lesson keeps security connected to everyday service design instead of treating it as a final review step.

- Internal networks are not automatically safe.
- Identity and authorization need propagation rules.
- Secrets and certificates need lifecycle ownership.

## Core study path

Read by following a request from an external user through internal services. At every boundary, ask what identity is used, what permission is checked, and what data is exposed.

- Decide where user identity should be preserved.
- Decide where service identity should be used.
- Keep security telemetry available for investigation.

## Practice cues

Pick an internal API and write its threat assumptions. Include caller identity, sensitive fields, abuse cases, and what gets logged.

- Avoid relying on network location alone.
- Make least privilege practical for teams.
- Check whether security controls fail open or fail closed.
