## Why this lesson matters

Distributed systems fail partially. This lesson helps you design services that protect users and teams when dependencies slow down, disappear, or return bad results.

- Retries can amplify load if they are not bounded.
- Isolation prevents one dependency from consuming every resource.
- Degradation choices should match product priorities.

## Core study path

Read each resilience pattern through the lens of a dependency failure. Ask what happens to latency, load, user experience, and operator visibility.

- Set timeouts before adding retries.
- Isolate critical resources and failure domains.
- Test recovery paths, not just happy paths.

## Practice cues

Choose one dependency and design its failure policy. Include timeout, retry, fallback, alert, and customer-facing behavior.

- Define the maximum wait a user should experience.
- Decide which features can degrade safely.
- Verify that your fallback does not hide serious data problems.
